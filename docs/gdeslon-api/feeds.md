# Товарные выгрузки (фиды)

Источник: https://gdeslon.ru/faq/21/ · Контекст: Catalog

Выгрузки создаются в кабинете (https://gdeslon.ru/export_files/) по выбранным магазинам и отдаются по
постоянной ссылке в формате YML (Яндекс.Маркет). Партнёрские ссылки уже внутри; данные обновляются с частотой,
заданной магазином. Используются для партнёрских магазинов и сайтов сравнения цен.

Для библиотеки: оффер выгрузки — тот же оффер, что в [search.md](search.md), плюс `param` и `categoryId`; файлы
большие — читать потоково (`XMLReader`), не загружая целиком в память.

## Реальная выгрузка (проверено 2026-10-13, задача yml-feeds)

Выгрузка «сквозная» по категориям женской одежды; сырьё и скрипт статистики — `tests/_probe/yml-feeds/`
(`stats.php`, `stats1.txt`).

### Ссылка и хост

- Постоянная ссылка: `https://export.gdeslon.ru/uploads/exports/<секрет>.zip` — секрет (48 символов вместе с `.zip`)
  **в последнем звене пути**, query-параметров нет. Сессия кабинета и ключи API не нужны: ссылка сама — секрет,
  маскировать её целиком после хоста. `SecretMasker` путь не маскирует.
- nginx/1.16.1, статический файл. По `http://` отдаётся так же (без редиректа на https) — библиотека ходит только
  по https.
- Неверный секрет (другое имя файла) → `404 text/html`, без редиректа на страницу входа.
- **Обрыв ~16 КБ на TCP-соединение, как у `api.gdeslon.ru`** ([README.md](README.md)): из РФ (сеть разработчика и
  тестовый сервер, оба RU) любое соединение зависает на 16 092–16 131 байтах тела, и с `Range`, и без; одна
  `Range`-часть 16 384 байта проходит за ~1,4 с. Полная загрузка 41 МБ — 2 506 частей по 16 КиБ, каждая в новом
  соединении: 8 параллельно — 116 с, ответов 420/503 не было. Загрузка одним GET невозможна.

### Заголовки и условные запросы

| Запрос | Ответ |
|---|---|
| `GET` / `HEAD` | 200, `Content-Type: application/zip`, `Content-Length: 41044994`, `Last-Modified`, `ETag: "6ace7d89-2724c02"` (сильный, nginx: mtime-hex — size-hex), `Accept-Ranges: bytes`; `Cache-Control`/`Expires`/`Content-Encoding` нет |
| `Range: bytes=0-1023` | 206, `Content-Range: bytes 0-1023/41044994`; с `Accept-Encoding: gzip` — так же, без `Content-Encoding` |
| `If-None-Match: <ETag>` | 304 |
| `If-Modified-Since: <Last-Modified>` | 304 |
| `Range` + `If-Range: <ETag>` | 206; с чужим ETag в `If-Range` — 200 и весь файл |
| `Range` за концом файла | 416, `Content-Range: bytes */41044994` |

`Last-Modified` = время формирования (`18:50:49 GMT` = `yml_catalog@date` `2026-10-13 21:50` по Москве). Через 12 часов
(2026-10-14 06:50 UTC) ETag и `Last-Modified` те же — выгрузка не пересобиралась; как часто она пересобирается —
**проверить** (сравнить ETag через сутки и больше).

### Архив

- ZIP с **одним** `.xml` внутри; имя записи — случайное (40 символов, похоже на секрет, в логи не выводить).
- Метод deflate (8), флаги 0 (без data descriptor, размеры и CRC в локальном заголовке), не zip64.
- 41 МБ архив → **345,7 МБ** XML (сжатие 88 %).
- ext-zip на Debian-образах php:8.1/8.4-cli нет — читать запись потоково через ext-zlib (raw deflate), либо ext-zip.

### XML

- Пролог `<?xml version='1.0' encoding='utf-8'?>`, затем `<!DOCTYPE yml_catalog SYSTEM "shops.dtd">` (как у поиска),
  без BOM. Весь файл почти одной строкой.
- Структура — стандарт YML (в отличие от поиска): `yml_catalog[@date="YYYY-MM-DD HH:MM"]/shop/{name, url, currencies,
  categories, offers}`; `shop/name` = `GdeSlon.ru`, `shop/url` = `https://www.gdeslon.ru/`, `company` нет;
  `currencies/currency[@id="RUR"][@rate="1"]`. Порядок: `categories` до `offers`.
- `categories/category[@id][@parent_id]` с названием в CDATA — **категории «Где Слон?»** (те же id, что
  `gs_category_id` и `categories.xml`), а не собственные категории магазина; атрибут — `parent_id`, не YML-`parentId`.
  386 категорий, у 2 нет `parent_id` (корни `1113` и `1564`); дерево замкнуто — все `parent_id` есть среди этих 386,
  циклов нет, глубина до 5; пустых названий нет, хвостовой пробел — у 2 (`Нижнее белье `).
- 137 832 оффера 21 магазина; разбор XMLReader + SimpleXML на оффер — 22 с, пик памяти 35 МБ (вместе с
  множествами id для подсчёта дублей).

### Оффер

```xml
<offer id="3377556719066258936" merchant_id="86276" gs_product_key="" article="3080332" gs_category_id="1144">
  <picture>//imgng.gdeslon.ru/commodities/…/big.jpg</picture>
  <thumbnail>//imgng.gdeslon.ru/commodities/…/small.jpg</thumbnail>
  <original_picture>https://www.leomax.ru/upload/iblock/…jpg</original_picture>
  <name><![CDATA[Джеггинсы &quot;Анабель&quot;]]></name>
  <description><![CDATA[]]></description>
  <vendor><![CDATA[ANIKO]]></vendor>
  <model><![CDATA[]]></model>
  <oldprice>3599.00</oldprice>
  <param name="&#x426;&#x432;&#x435;&#x442;"><![CDATA[Серый]]></param>
  <url>https://xf.gdeslon.ru/cm/<код вебмастера>/?mid=86276&amp;goto=…&amp;erid=…</url>
  <tagging_ads><info><![CDATA[Реклама. Рекламодатель ООО "…" ИНН … , https://… erid …]]></info></tagging_ads>
  <destination-url-do-not-send-traffic>https://www.leomax.ru/goods/…/</destination-url-do-not-send-traffic>
  <currencyId>RUR</currencyId>
  <categoryId>1144</categoryId>
  <price>1499.00</price>
</offer>
```

Отличия от оффера `search.xml`:

- **есть** `param` (у 80 % офферов) и `categoryId` (ровно один, = `gs_category_id`);
- **нет** атрибута `available`, элементов `charge` и `<merchant_id>`;
- `picture` и `thumbnail` — **протокольно-относительные** `//imgng.gdeslon.ru/…` (в поиске `https://`) — достраивать
  `https:`; ровно по одному `picture`, `thumbnail`, `original_picture` у каждого оффера;
- ссылка на хосте `xf.gdeslon.ru/cm/…` (в поиске `af.gdeslon.ru`), та же форма `?mid&goto&erid`;
- цены с копейками `1499.00` (в поиске `1499`); `oldprice` есть всегда, бывает пустым `<oldprice/>`;
- `offer@id` — точное целое до 2^64 (больше `PHP_INT_MAX`, только строкой); **в поиске тот же оффер приходит с
  округлённым id** (`3377556719066259000` вместо `…258936` — float-точность сервера поиска), поэтому id между
  поиском и выгрузкой **не совпадает**. Совпадают `merchant_id` + `article` (проверено `search.xml?articles=3080332&m=86276`) —
  ключ `OfferKey` общий.

Частоты: `tagging_ads` у всех, erid в ссылке и в маркировке — у 101 866 (74 %); цена 0 — 964 оффера; дублей
`offer@id` и `merchant_id:article` нет; `description` с HTML-сущностями — 4 487; `name` есть у всех.

### `param`

- Имена в атрибуте закодированы числовыми ссылками (`&#x426;…`) — XML-парсер раскрывает их сам; значения в CDATA.
- `unit` не встречается ни разу; размеры — в **именах** параметров: `Размер`, `Размер_RU`, `Размер_US`, `Размер_UK`.
- Пустых значений и `param` без `name` нет. 101 различное имя; самые частые (число офферов из 137 832):
  `Цвет` 103 805, `Пол` 96 589, `Возраст` 85 596, `Сезон` 47 806, `акция`/`segments`/`Наличиескидки` 46 095,
  `коллекция` 46 080, `Скидка` 31 645, `Назначение` 31 632, `Размер_RU` 31 631, `Размер_US` 29 701, `Размер` 26 207,
  `Новинка` 19 484, `Размер_UK` 10 066, `Коллекция` 7 424, `Артикул` 7 310, `фильтр цвета` 6 550, `Состав` 4 335,
  `Материал` 1 857, `Материал верха` 1 049; служебные `RR_weight`, `nativeUrl`, `oldPrice` — у отдельных магазинов.
- Повторов одного имени внутри оффера нет (`repeats1.txt`). Несколько размеров — **одно значение через пробел**,
  а единица (`unit` магазина) приклеена к каждому размеру без пробела: `LRU SRU MRU XLRU`, `38-40RU 36-38RU 40-42RU`,
  `24RU 23RU`, `LINT MINT SINT`, `ONESIZERU NoneRU` (мусорное `None` — тоже из фида); бывает и одиночное `50-52`,
  `48`, `1 шт.`, `250 мл`. У 26 404 офферов в `Размер*` есть пробел-список. Разбирать — задача потребителя.
- Набор `param` зависит от магазина: у 5 из 21 магазина `param` нет совсем (крупнейший из них — 25 239 офферов),
  у части — только служебные (`Артикул`, `popularity`, `Форма выпуска`).

## Что известно без выгрузки (проверено 2026-10-13, задача yml-feeds)

Сырые ответы — `tests/_probe/yml-feeds/`.

- FAQ 21 перечитан живьём: заголовок «XML/CSV выгрузки магазинов», файл «в формате Yandex Market XML» (ссылка на
  https://yandex.ru/support/marketplace/assortment/auto/yml.html), обновляется «с периодичностью, заданной самим
  магазином», партнёрские ссылки уже внутри («никакие идентификаторы никуда дописывать не придется»). **Формат
  ссылки, авторизация, сжатие, размер и частота обновления в FAQ не описаны.**
- `GET https://gdeslon.ru/export_files/` без сессии кабинета → `302`, `Location: /accounts/login/?next=/export_files/`
  (nginx, `text/html`). Это страница кабинета (вход по логину), а не API: токеном XML API её не открыть.
- API-эндпоинта выгрузок, доступного ключами вебмастера, не найдено:
  - `GET https://gdeslon.ru/api/v1/` (DRF, корень роутера) — 200 `application/json`, с токеном и без одинаково:
    только `lost-orders`, `coupons`, `kinds`;
  - `GET https://gdeslon.ru/api/` — 200 `application/json`, 29 маршрутов (`files`, `commodities`, `merchants`,
    `my_merchants`, `orders`, `orders-import`, `currencies`, `tasks`, … — внутренний API сайта);
  - `GET https://gdeslon.ru/api/files/` — 403 `{"detail":"Учетные данные не были предоставлены."}` без авторизации,
    с `Authorization: Bearer <токен XML API>` и с `?api_token=<токен XML API>`; с HTTP Basic ключей API по продажам —
    403 `{"detail":"У вас нет прав для выполнения этой операции."}`. Остальные маршруты не проверялись.

## Исторические сведения (не проверено живьём)

Из архива блога (web.archive.org, записи 2012–2014) и исходников официального WordPress-плагина «Где Слон?»
(https://github.com/GdeSlon/wp-affiliate-shop, последний коммит 2014-08-20). Использовать только как гипотезы
для проверки на реальной выгрузке:

- выгрузки бывают XML и CSV (в CSV разделитель `;`, который встречался и в описаниях); строятся по рекламодателю
  (с отбором разделов) или «сквозные» — по категориям всех рекламодателей; формирование новой выгрузки — обычно
  минуты, «в некоторых случаях до двух часов»; в 2014 — «переход на новый движок XML-выгрузок»;
- плагин скачивал файл по «Ссылке на выгрузку» целиком как **ZIP** (`archive.zip`, проверял MIME `zip`), распаковывал
  и брал первый `.xml` внутри;
- разбирал YML: `<categories>` с `<category id="…" parentId="…">название</category>`, затем `<offer id="…">` с
  `url`, `price`, `currencyId`, `picture`, `name` (если нет — `model`), `description`, `categoryId`, `vendor`,
  `<param name="…">значение</param>`.

## Открытые вопросы

- Как часто выгрузка пересобирается (сравнить `ETag`/`Last-Modified` через сутки) и стабилен ли `article` у того же
  товара между пересборками.
- Форма CSV-выгрузки (библиотека её не поддерживает; создавать выгрузки в XML).
