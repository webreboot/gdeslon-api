# Postback (входящие уведомления о конверсиях)

Источник: https://gdeslon.ru/faq/24/ (перечитано 2026-10-07, вместе со скриншотами страницы) · смежные: FAQ 60
(макрос `*click_id*`), FAQ 23 (sub_id) · Контекст: Sales · Входящий адаптер: `Interface/Postback`

Где Слон сам отправляет запрос на URL вебмастера при смене статуса заказа. Настраивается в кабинете
(https://gdeslon.ru/postbacks/, создание — `/postbacks/new/`; без входа обе страницы — 302 на `/accounts/login/`,
проверено 2026-10-07).

Статусы фактов: **по документации** — текст FAQ 24; **по скриншоту FAQ (2021)** — видно на картинках FAQ 24
(настройка, тестовая отправка, приёмник webhook.site, апрель 2021), живьём не проверено; **проверено** — пока ничего:
входящий запрос можно увидеть только тестовой отправкой из кабинета вебмастера на внешний приёмник.

## Настройка в кабинете (по документации)

- «Название», «Адрес» (свободный текст, URL приёмника), «Активен».
- «При условии заказа у рекламодателя» — один рекламодатель; не выбрать никого — по всем (по скриншоту).
- «При условии статуса заказа» — несколько из: потенциальный (created), отменен (cancelled), отложен (pending),
  подтвержден (confirmed), выплачен (payed); не выбрать ничего — при любом (по скриншоту).
- «Тип HTTP запроса»: `GET` — параметры в query; `POST` — «Тип передаваемых параметров»: `params`, `json` или `xml`.
- `GET` и `POST params`: список «Получаемое имя» (произвольное, задаёт вебмастер) → «Значение» (макрос из выпадающего
  списка — **постоянное значение параметру не задать**, по скриншоту). Поэтому библиотека не знает имена полей заранее:
  нужна **карта соответствий** «имя у вебмастера → макрос» (по умолчанию — имя макроса без звёздочек).
- `POST json`/`xml`: тело вебмастер пишет сам, макросы подставляются в текст. Примеры из FAQ:
  `{ order_number: *order_id*, offer: *merchant_id*, earn: *profit* }` (это **невалидный JSON** — ключи и значения без
  кавычек), `<root> <earn>*profit*</earn> <offer>*merchant_id*</offer> <order_number>*order_id*</order_number> </root>`.
  Экранируются ли подставленные значения (кавычки, `&`, `<` в названии оффера и User-Agent) — **неизвестно**.
- «HTTP headers»: пары «Название» → «Значение» (подсказки в форме: `Authorization`, `Basic QWxhZGRpbjpv==`). Это
  единственный способ аутентификации: **подписи запроса нет**, IP-адреса отправителя не опубликованы.

## Макросы

| Макрос | Смысл (FAQ 24) | Статус |
|--------|----------------|--------|
| `*gs_order_id*` | номер заказа в системе Где Слон | по документации |
| `*merchant_id*` | номер рекламодателя в системе Где Слон | по документации |
| `*sub_id*`, `*sub_id2*` … `*sub_id5*` | значения параметров sub_id ссылки | по документации |
| `*profit*` | заработок вебмастера | по документации |
| `*order_id*` | номер заказа рекламодателя | по документации |
| `*order_sum*` | общая сумма заказа | по документации |
| `*click_time*` | время перехода | по документации |
| `*action_time*` | время создания заказа на стороне рекламодателя | по документации |
| `*user_agent*` | идентификационная строка клиентского приложения | по документации |
| `*state*` | статус конверсии: 0 потенциальный (created), 1 отменен (cancelled), 2 отложен (pending), 3 подтвержден (confirmed), 4 выплачен (payed) | по документации |
| `*price_in_currency*` | сумма в валюте | по документации |
| `*offer_name*` | название оффера | по документации |
| `*currency*` | валюта | по документации |
| `*click_id*` | «соответственно клик» (FAQ 60); откуда берётся значение, не описано | FAQ 60 + скриншот настройки |
| `*action_ip*`, `*user_referrer*`, `*token*` | не описаны; есть только полями в окне тестовой отправки | по скриншоту FAQ (2021) |

В какой валюте `*profit*` и `*order_sum*` и к чему относится `*currency*` (к ним или только к `*price_in_currency*`) —
не описано. У API по продажам валюта одна на сумму и вознаграждение ([orders.md](orders.md)).

## Тестовая отправка (по документации и скриншотам)

- Кнопка «Тестировать» в списке `/postbacks/` или в «Просмотре кода»; окно «Тестовая отправка постбэка» с полями
  `gs_order_id, merchant_id, sub_id, sub_id2..5, profit, order_id, order_sum, click_time, action_time, action_ip,
  user_agent, user_referrer, click_id, state, price_in_currency, offer_name, token, currency` (по скриншоту).
- Обязательны `merchant_id` (должен совпадать с рекламодателем постбэка) и `state` (числом, из выбранных статусов);
  иначе в ответе ошибка. Фильтры постбэка действуют и на тест: при фильтре «подтвержден» тест с `state` ≠ 3 не уйдёт.
- **Значения тестовой отправки — то, что ввёл человек, без проверки**: на скриншоте `profit` = `eewrwer` дошло как
  есть. Поэтому тест показывает транспорт (метод, заголовки, Content-Type, кодирование, экранирование), но **не формат
  настоящих значений** (время, суммы, валюта) — его видно только в постбэке по реальному заказу.
- Незаполненный макрос приходит **пустым параметром**, а не отсутствует: `clickId=` (по скриншоту).
- Порядок параметров в query не совпадает с порядком в настройке (настроено someOrderId, myProfit, clickId — пришло
  `?clickId=&myProfit=eewrwer&someOrderId=1234567`, похоже на сортировку по имени; по скриншоту).
- GET пришёл с телом 0 байт; IP отправителя на скриншоте 2021 года — `178.63.47.83` (Hetzner). Список адресов не
  опубликован — для аутентификации не годится.
- Окно показывает ответ приёмника: код, заголовки, тело (`{'code': 200, 'headers': {...}, 'body': ''}`). Успех — 200.
  Тело ответа приёмника видно вебмастеру — в нём можно вернуть причину ошибки (без секретов).

## Открытые вопросы (проверить тестовой отправкой и постбэком реального заказа)

- заголовки запроса: User-Agent, `Content-Type` у `params` (urlencoded или multipart), `json`, `xml`; кодировка (UTF-8?);
- экранирование подставленных значений в JSON/XML и в query (`+`, пробел, `&`, кавычки, кириллица);
- принимает ли кабинет невалидный JSON-шаблон из примера FAQ и что тогда отправляет;
- формат `*click_time*` / `*action_time*` (дата-время, часовой пояс, unix time?) и сумм (точка/запятая, число знаков) —
  только по реальному заказу;
- валюта `*profit*`/`*order_sum*`, смысл `*currency*`, `*price_in_currency*`, `*click_id*`, `*token*`;
- повторяет ли Где Слон отправку при не-200 / таймауте, с какими интервалами; таймаут ожидания ответа;
- может ли прийти несколько уведомлений об одном статусе одного заказа; с каких IP идут запросы сейчас.
