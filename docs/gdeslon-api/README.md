# API вебмастера «Где Слон?» — справочник проекта

Конспект официальной документации (https://gdeslon.ru/for_affiliates/tools/, FAQ 17–27, 74) плюс то, что
проверено живыми запросами. Это опора для аналитики, кода и ревью: любой эндпоинт, параметр и поле
используются только после сверки с этим справочником. Если факт расходится с ответом API — правим справочник
по факту ответа и помечаем дату проверки.

Статусы фактов:
- **проверено YYYY-MM-DD** — подтверждено живым запросом;
- **по документации** — только из FAQ, живьём ещё не подтверждено.

## Хосты и авторизация (проверено 2026-10-07)

Документация местами указывает старые хосты (`www.gdeslon.ru`, `beta.gdeslon.ru`) — они отвечают редиректом.
Используем канонические адреса:

| Что | Адрес | Авторизация | Без авторизации |
|-----|-------|-------------|-----------------|
| Поиск товаров | `GET https://api.gdeslon.ru/api/search.xml` | `_gs_at=<токен XML API>` в query | 403 `Affiliate token (_gs_at) is required parameter` (text/html); несуществующий токен — 403 `This affiliate token does not exists`; токен неверного формата — **404** с эхом токена в теле (проверено 2026-10-07) |
| Магазины | `GET https://www.gdeslon.ru/api/users/shops.{json,xml}` | `api_token=<токен XML API>` в query | 200: `shops.json` — только `_id` и `name`; `shops.xml` — публичный список без партнёрских ссылок (неверный токен — то же самое, ошибки нет) |
| Категории | `GET https://api.gdeslon.ru/gdeslon-categories.json` | нет | 200 |
| Заказы | `POST https://gdeslon.ru/api/orders/` (со слэшем; без него — 301) | HTTP Basic `USER_ID:API_KEY` | 401 `{"detail":"Некорректные учетные данные."}`; неверные ключи — 401 `{"detail":"Недопустимые имя пользователя или пароль."}` (проверено 2026-10-07) |
| Потерянные заказы | `https://gdeslon.ru/api/v1/lost-orders/` (только со слэшем; без — 301) | `Authorization: Bearer <токен XML API>` | 401 `{"errors":{"detail":"Недопустимый заголовок токена. Не предоставлены учетные данные."}}`; неверный токен — 401 `{"errors":{"detail":"Недопустимый токен."}}`, `WWW-Authenticate: Bearer` (проверено 2026-10-07) |
| Купоны (XML-выгрузка) | `GET https://gdeslon.ru/api/coupons.xml` (и `.csv`) | `api_token=<токен XML API>` в query | 401 XML `<gdeslon-coupons><detail>Учетные данные не были предоставлены.</detail></gdeslon-coupons>`; неверный токен — 401 `<detail>Недопустимый токен.</detail>` (проверено 2026-10-07) |
| Купоны (JSON) | `GET https://gdeslon.ru/api/v1/coupons/`, `/api/v1/kinds/` (со слэшем) | `Authorization: Bearer <токен XML API>` | 401 `{"detail":"Недопустимый заголовок токена. Не предоставлены учетные данные."}` — **без** обёртки `errors`, в отличие от lost-orders; неверный — 401 `{"detail":"Недопустимый токен."}` (проверено 2026-10-07) |
| Купоны (Atom) | `GET https://gdeslon.ru/api/coupons/feed.atom` | `_gs_at=<токен XML API>` | 401 `{"detail":"Учетные данные не были предоставлены."}`; неверный — 401 `{"detail":"Недопустимый токен."}` (проверено 2026-10-07) |

Цепочки редиректов: `gdeslon.ru/api/search.xml` → `www.gdeslon.ru/...` → `api.gdeslon.ru/...`;
`beta.gdeslon.ru/api/coupons/...` → `new.gdeslon.ru/...` → `gdeslon.ru/...`.
`https://www.gdeslon.ru/api/orders/` (адрес из документации) — отдельный бэкенд без валидации фильтров, отвечает
за 0,2 с (раньше не отвечал за 15 с); `gdeslon.ru` — DRF, 3,6–5,6 с на запрос. Подробности — [orders.md](orders.md#два-бэкенда-wwwgdeslonru-проверено-2026-10-07)
(проверено 2026-10-07). Обрыва ~16 КБ у `gdeslon.ru` нет (420 КБ одним соединением, проверено 2026-10-07).

**Обрыв больших ответов `api.gdeslon.ru` (проверено 2026-10-07).** Хост на Hetzner (4 адреса: 49.12.87.213,
49.12.87.214, 85.10.211.9, 85.10.211.10), только HTTP/1.1. Из сети разработчика одно **TCP-соединение** по https
зависает на ~16 КБ тела (весь файл категорий — всегда на 16 087 байтах), отдельные `Range`-части до 22 КиБ проходят,
24 КиБ — нет; ограничение действует на соединение, а не на запрос (keep-alive не спасает, нужен `Connection: close`).
Файл категорий отдаёт nginx (поддерживает `Range`, `If-Match` → 412, `If-None-Match` → 304), остальное на хосте —
Express: `Range` игнорирует, ETag у поиска нет, сжимается только `text/html` (поиск `text/xml` — нет). Поиск
`l=100` (~190 КБ) зависает на 16 011 байтах так же, как категории; `l=10` (19,5 КБ) обычно проходит, но с длинными
описаниями тоже зависает (16 019 байт при `l=10&p=11`) — граница ~16 КБ тела, а не число офферов. Подробности —
[categories.md](categories.md#обрыв-загрузки-проверено-2026-10-07), [search.md](search.md#http-и-размер-ответа-проверено-2026-10-07).
`www.gdeslon.ru` (магазины) — другой хост (5.189.239.194, 31.184.219.58), **ограничения нет**: `shops.xml` с токеном
(1,36 МБ) загружается за 0,9 с.

Где взять ключи:
- токен XML API — https://gdeslon.ru/api_settings/xml (он же для `api_token` магазинов и выгрузки купонов, `_gs_at` поиска и
  Atom-ленты, Bearer потерянных заказов и `/api/v1/coupons/` — **проверено 2026-10-07**). Он же стоит **в пути
  ссылок купонов** (`xf.gdeslon.ru/ck/<токен>/<id>`) — см. [coupons.md](coupons.md);
- ID пользователя и ключ API по продажам — https://gdeslon.ru/api_settings/orders.

## Правила работы с живым API

- Только запросы на чтение. `POST /api/v1/lost-orders/` **не вызывать никогда** — создаёт реальную заявку.
- Ключи берутся из `.env` разработчика; в чат, логи, фикстуры и сообщения исключений не попадают.
- curl из Git Bash на Windows (Schannel) падает с `CRYPT_E_REVOCATION_OFFLINE` — для проб добавлять
  `--ssl-no-revoke` (отключает только проверку отзыва сертификата, не TLS). Сам SDK работает через OpenSSL в PHP.
- Ответы перед сохранением в `tests/Fixtures/` обезличиваются: ID и номера заказов, суммы, sub_id, ключевые слова,
  токены в ссылках (`_gs_at`, партнёрские ссылки) заменяются на выдуманные значения той же формы.
