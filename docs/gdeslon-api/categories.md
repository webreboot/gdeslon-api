# Категории товаров

Источник: https://gdeslon.ru/faq/20/ · Контекст: Catalog · Порт: `CategoryRepository`

`GET https://api.gdeslon.ru/gdeslon-categories.json` — публичный, без авторизации, параметров нет (проверено 2026-10-07).
По `http://` отдаётся тот же файл с кодом 200 без редиректа на https (проверено 2026-10-07) — используем только https.

## Формат (проверено 2026-10-07)

Объект, ключ — ID категории строкой, значение — категория. JSON компактный (без пробелов), кириллица — сырым UTF-8
без `\uXXXX`, без BOM, в конце `\n`. Ключи идут по возрастанию ID.

```json
{
  "1": {"offer_count": 521843, "_id": 1, "parent_id": null, "name": "Подарки, сувениры, цветы", "is_archived": false, "path": [1]},
  "2": {"_id": 2, "parent_id": 1, "name": "Украшения и бижутерия", "is_archived": false, "path": [1, 2]}
}
```

| Поле | Тип | Есть всегда | Смысл |
|------|-----|-------------|-------|
| `_id` | int | да | ID категории (для `tid`/`no_tid` поиска); ключ объекта всегда равен `_id` строкой |
| `parent_id` | int\|null | да (ключ присутствует) | родитель; `null` — корневая |
| `name` | string | да | название; бывают пробелы в начале/конце и повторы названий |
| `is_archived` | bool | да | архивная категория |
| `path` | int[] | да | путь от корня до категории включительно, последний элемент = `_id` |
| `offer_count` | int | **нет** | число офферов; есть только у 10 крупных категорий, отсутствие ≠ 0 |

## Факты о данных (снимок 2026-10-07, ETag `"6724af75-26edb"`)

- 1389 категорий, ID от 1 до 2003 (с пропусками), 31 корневая.
- Глубина `path`: 1 уровень — 31, 2 — 583, 3 — 284, 4 — 356, 5 — 135. Максимум 5
  (пример: Одежда › Детская одежда › Для девочек › Верхняя одежда › Парки).
- Для всех категорий с существующим родителем `path` = `path` родителя + `_id`; у корня `path` = `[_id]`.
- **8 «сирот»**: `parent_id` ссылается на категорию, которой нет в ответе (отсутствуют ID 50, 170, 277, 352).
  Например `1052` («Сушильные и гладильные машины»): `parent_id` 277, `path` `[263, 277, 1052]`, а 277 в ответе нет.
  Сироты: 1052, 1054, 1056, 1058, 1975 (родитель 277), 1992 (50), 1993 (170), 1994 (352). Детей у сирот нет.
- Архивных категорий нет: `is_archived` = `false` у всех 1389.
- `offer_count` только у 10: корни 1, 66, 121, 316, 495, 1113, 1564, 1661 и дочерние 136 (под 121), 1114 (под 1113).
  Значения от 491 104 до 2 892 873, нулей нет. В объектах с `offer_count` он идёт первым ключом.
- 13 названий с пробелом в начале или конце (`" Станки"`, `"Нижнее белье "`), 122 названия повторяются
  (`"Книги"` — корень 121 и дочерняя 655). Есть латиница (`"Usb flash drive"`) и `ё`. HTML-сущностей нет.

## HTTP (проверено 2026-10-07)

```
HTTP/1.1 200 OK
Server: nginx/1.24.0
Content-Type: application/json
Content-Length: 159451
Last-Modified: Fri, 01 Nov 2024 10:37:41 GMT
ETag: "6724af75-26edb"
Content-Type: application/json; charset=utf-8
Accept-Ranges: bytes
```

- Размер **159 451 байт (~156 КБ)**. Сжатия нет: на `Accept-Encoding: gzip, deflate, br` ответ тот же, без
  `Content-Encoding`.
- Заголовок `Content-Type` приходит **дважды**.
- `Cache-Control` и `Expires` нет. Есть `ETag` и `Last-Modified` (файл не менялся с 2024-11-01).
- Условные запросы работают: `If-None-Match: "6724af75-26edb"` и `If-Modified-Since` → `304 Not Modified`.
- Поддерживаются диапазоны: `Range: bytes=0-9999` → `206 Partial Content`, `Content-Range: bytes 0-9999/159451`.
- Несуществующий путь на хосте: `404`, `text/html; charset=utf-8`, тело — HTML Express `Cannot GET /...`.
- Хост `api.gdeslon.ru` резолвится по кругу в 4 адреса Hetzner: 49.12.87.213, 49.12.87.214, 85.10.211.9,
  85.10.211.10 (проверено 2026-10-07). Только HTTP/1.1: клиент с nghttp2 предлагает h2, сервер выбирает 1.1.
- `HEAD` → 200 с теми же заголовками без тела, ~0,2 с (проверено 2026-10-07).
- Файл отдаёт nginx (сильный ETag вида `"<mtime hex>-<size hex>"`), всё остальное на хосте (`/api/search.xml`,
  404) — приложение Express за тем же nginx (см. «Обрыв загрузки»).

### Диапазоны и условные запросы (проверено 2026-10-07)

| Запрос | Ответ |
|--------|-------|
| `Range: bytes=0-9999` | `206`, `Content-Range: bytes 0-9999/159451`, `Content-Length: 10000`, `ETag` и `Last-Modified` те же; `Accept-Ranges` в 206 нет |
| `Range: bytes=159000-` (открытый конец) | `206`, `bytes 159000-159450/159451`, 451 байт |
| `Range: bytes=159000-170000` (конец за размером) | `206`, конец урезан до `159450`, 451 байт |
| `Range: bytes=-500` (суффикс) | `206`, `bytes 158951-159450/159451` |
| `Range: bytes=0-0` | `206`, 1 байт `{` |
| `Range: bytes=200000-` (начало за размером) | `416 Requested Range Not Satisfiable`, `text/html` (HTML nginx, 197 байт), `Content-Range: bytes */159451` |
| `Range: bytes=0-99,200-299` | `206`, `Content-Type: multipart/byteranges; boundary=...` — **не использовать** |
| `Range` + `Accept-Encoding: gzip` | `206` без `Content-Encoding` (диапазон по несжатому файлу) |
| `Range` + `If-Range: "<тот же ETag>"` или `If-Range: <тот же Last-Modified>` | `206` |
| `Range` + `If-Range: "<другой ETag>"` | `200` и **весь файл** — то есть зависание на ~16 КБ (см. ниже) |
| `Range` + `If-Match: "<тот же ETag>"` | `206` |
| `Range` + `If-Match: "<другой ETag>"` | `412 Precondition Failed` сразу (`text/html`, 173 байта) |
| `Range` + `If-Unmodified-Since` раньше `Last-Modified` | `412` |
| `Range` + `If-None-Match: "<тот же ETag>"` | `304` (условие проверяется раньше диапазона) |
| `If-None-Match: "<ETag>"`, `If-None-Match: W/"<ETag>"`, `If-Modified-Since: <Last-Modified>` | `304`, тела нет; в 304 есть `ETag`, `Last-Modified`, `Content-Type` |

Части режутся по байтам, а не по символам: граница части может прийтись внутрь UTF-8 символа или JSON-строки —
склеивать только байты, разбирать только целый файл.

## Обрыв загрузки (проверено 2026-10-07)

Из сети разработчика (и с сервера тестов в той же сети) загрузка одним соединением **зависает после ~16 КБ**:
`curl: (28) Operation timed out after 100012 milliseconds with 16087 out of 159451 bytes received`. Похоже на сетевое
ограничение на пути до хостинга, а не на ошибку API. Отсюда и прежнее наблюдение «ответ пришёл обрезанным»:
клиент должен давать понятную ошибку на таймаут, обрыв и битый JSON, а не падать с TypeError.

Замеры 2026-10-07 (curl с Windows-хоста и с сервера тестов, PHP ext-curl в контейнере `composer` на сервере тестов):

- **Обрыв воспроизводится всегда и в одном месте.** Весь файл по https: зависание ровно на 16 087 байтах тела
  (5 из 5 попыток: локально, с сервера, из PHP — `TimeoutException` текущего `GdeSlon::categories()` через 8 с,
  «16087 out of 159451 bytes received»). По http — на 34 743 байтах.
- **Ограничение — на TCP-соединение, а не на запрос.** Три `Range`-запроса по 8 КиБ в одном keep-alive соединении:
  первые два — 206, третий получает 0 байт и зависает. С `Connection: close` (новое соединение на каждую часть)
  все части проходят. Значит, части должны идти в **разных соединениях**.
- **Размер части по https** (одна часть на соединение, разные смещения): 8, 10, 12, 14 КиБ — 3 из 3;
  16 КиБ — 9 из 9; 20 КиБ — 9 из 9; 22 КиБ — 6 из 6; **24 КиБ — 0 из 5** (зависание на 16 056–16 060 байтах).
  По http: 24 и 32 КиБ проходят, 48 КиБ зависает на 34 716. Порог не равен постоянному числу байт, запас брать
  с обеих сторон.
- **Время части** 0,2–0,3 с (изредка до 0,9 с). С хоста сервера тестов — ~1,3 с, из них ~1,05 с DNS
  (медленный резолвер хоста); из Docker-контейнера на том же сервере DNS ~0 с, часть 0,25 с.
- **Сборка целого файла** из 10 частей по 16 КиБ с `Connection: close`: 159 451 байт, SHA-256 совпадает с файлом,
  ETag во всех частях одинаковый; 3,6 с (curl локально), 2,5 с (PHP ext-curl в контейнере), JSON разбирается, 1389 категорий.

### Остальной хост — Express (проверено 2026-10-07)

`/api/search.xml` и 404 отдаёт Express (`X-Powered-By: Express`, CORS-заголовки):

- `Range` игнорируется: и 403/404, и **200 поиска с токеном** приходят целиком, без `Accept-Ranges`
  (в том числе с `Accept-Encoding: identity` и с `Connection: close`) — см. [search.md](search.md#http-и-размер-ответа-проверено-2026-10-07);
- сжимаются **только `text/html`** (403/404 при `Accept-Encoding: gzip` — `Content-Encoding: gzip`, даже 46 байт):
  похоже на `gzip on` nginx с типами по умолчанию. `text/xml` поиска и `application/json` не сжимаются ни на
  `gzip`, ни на `br`;
- у 403 ETag слабый `W/"2e-..."`, у 200 поиска ETag нет вовсе;
- `HEAD /api/search.xml` без токена → 403 с заголовками.

Итог для клиента: на этом хосте загрузка частями возможна **только для файла категорий**; поиск надо держать
в пределах ~16 КБ на ответ размером страницы `l` (см. search.md).
